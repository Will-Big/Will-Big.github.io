01 · AI 활용 방식

AI와의 역할 분담과 검증 과정

설계·구현·검토에 Claude와 Codex를 함께 사용하며, 요구사항과 설계 방향은 제가 정합니다. 한쪽이 작성한 코드를 다른 쪽이 검토하게 한 뒤, 지적 사항을 실제 코드와 대조해 반영 여부를 판단합니다.

02 · Harness 개선 과정

규칙 문서에서 공통 검증까지의 변화

Claude와 Codex가 같은 규칙과 검증 도구를 쓰도록 AI 작업 환경(harness)을 정리했습니다. 공통 지침은 AGENTS.md와 docs/agents에 두고, 반복해서 빠뜨리는 항목은 검사 코드로 옮겼습니다.

규칙이 늘어난 뒤에는 적용 범위도 조정했습니다. Unity 에디터가 읽는 Assets·Packages·ProjectSettings는 별도 worktree에서 수정하도록 제한하고, 문서 작업까지 막히던 불편을 줄였습니다.

사례 1 · 요구사항 전달

카드 원본을 JSON으로 통일

카드가 동적 데이터를 가지므로 실행 중 데이터를 읽어 객체를 구성해야 했지만, 초기 구조는 Unity 인스펙터에서 ScriptableObject를 작성한 뒤 C# 코드를 생성하는 방식이었습니다.

해결 후 게임과 테스트가 같은 카드 파일을 사용합니다. 이후 설계 검토에서는 실행 환경과 데이터 변경 방법부터 확인하며, 이전 작성 경로가 다시 생기지 않도록 자동 검사도 추가했습니다.

사례 2 · 설계 검토

고정 카드 분류 제거와 계획서 분리

카드의 효과와 발동 조건 조합은 코드 수정 없이 데이터로 구성할 수 있어야 했지만, 조건 판정이 공격·스킬·방어라는 고정 분류를 기준으로 작성돼 표현할 수 있는 조합이 제한됐습니다.

해결 후 카드 조건은 실제 효과를 기준으로 판정합니다. 설계는 HTML 개요에서 구조도·대안·이후 변경이 어려워지는 지점을 먼저 검토한 뒤 구현 문서에 반영하며, 작은 수정은 별도 문서 없이 진행합니다.
