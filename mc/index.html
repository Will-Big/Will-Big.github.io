다목적 인스펙터와 리플렉션

무엇을

컴포넌트 메타데이터만 등록하면 인스펙터 UI가 자동 생성되는 구조

왜

컴포넌트가 늘 때마다 에디터를 고쳐야 해서 기획 요청을 제때 받아주지 못함

무엇이 나아졌나

컴포넌트 추가 시 에디터 수정 0줄 — 등록 매크로 한 블록으로 끝

핵심 코드 — 등록부
REGISTER_COMPONENT_META(ColliderCommon)
  IS_HIDDEN()                     // AddComponent 목록에서 숨김
  SET_MEMBER(...::isTrigger, "Is Trigger")
  SET_DESC("트리거로 작동할지 여부")   // 툴팁 메타 데이터
  SET_MEMBER(...::center, "Center")
  SET_DRAG_SPEED(0.01f);         // 조절 단위 메타 데이터

타입 해시로 기본 자료형을 먼저 걸러내고, 어디에도 걸리지 않으면 사용자 정의 구조체로 보고 재귀 호출합니다. 그래서 중첩 구조체도 깊이 제한 없이 그려집니다.

막혔던 지점

같은 자료형이라도 콤보 박스, 플래그, 값 제한, 조절 단위처럼 다르게 보여줘야 할 때가 많았습니다. 이걸 분기문으로 처리하다 보니 조건이 계속 붙어서, 결국 표현 방식을 메타데이터에 적어 두는 쪽으로 바꿨습니다.

프리팹(시리얼라이즈)

무엇을

엔티티와 자식 계층 전체를 .prefab 파일로 저장하고 다시 불러오는 기능

왜

같은 가구·도구를 방마다 다시 조립하느라 기획 시간이 계속 날아감

무엇이 나아졌나

한 번 만든 오브젝트를 레벨 전체에서 재사용, 배치할 때 다시 조립할 일이 없어짐

핵심 코드 — 계층 복제
for (auto&& [id, storage] : registry.storage())
{
  if (id == type_id<Relationship>().hash())
    continue;                // 관계만 따로 처리
  if (storage.contains(src))
    storage.push(dst, storage.value(src));
}
for (auto& child : srcRs->children)
  copyEntity(registry, child, registry.create());

컴포넌트는 스토리지를 순회해 통째로 밀어 넣고, 부모–자식 관계만 _copyMapping으로 다시 이어 붙입니다. 복사·붙여넣기(Ctrl+C/V)도 같은 함수를 씁니다.

막혔던 지점

자식을 먼저 만들면 부모 핸들이 아직 없고, 부모를 먼저 만들면 자식 목록이 비어 있었습니다. 그래서 원본과 사본의 매핑 테이블을 먼저 채우고 관계는 나중에 잇는 두 단계로 나눴습니다.

캐릭터 컨트롤러

무엇을

강체 대신 캐릭터 컨트롤러를 PhysX 위에 감싸, 급정거·언덕 무시·강한 중력을 구현

왜

원기둥 강체가 물리 법칙을 그대로 따르니 조작이 미끄럽고 답답함

무엇이 나아졌나

앱 코드가 PhysX를 직접 만지지 않고 이동·접지 판정을 씀

핵심 코드 — 노출 인터페이스
struct CharacterController
{
  float slopeLimit = 45.0f; // 오를 수 있는 각도
  float stepOffset = 0.5f;  // 무시할 턱 높이
  bool  isGrounded = false; // 내부에서 갱신
  CollisionFlags collisionFlags;
};
// 앱은 이 한 줄만 부른다
_physicsScene->MoveCharacter(...);

자주 안 쓰는 인자는 기본값으로 숨겨서, 앱 쪽에서 코어를 직접 만질 일이 없게 했습니다. isGrounded는 이동 함수가 내부에서 갱신해 게임 로직·애니메이션이 그대로 씁니다.

막혔던 지점

엔진이 어디까지 해주고 게임이 어디부터 정할지가 계속 헷갈렸습니다. 앱은 변위와 레이어만 넘긴다로 선을 긋고, 나머지 판정은 전부 코어 안에 뒀습니다.

내가 한 일 · 설계 및 구현 GAMEPLAY

상호작용

무엇을

레이캐스트 적중 목록을 거리순으로 정렬해, 도구 / 그 외 오브젝트를 각각의 시스템이 처리

왜

집기·정리·폐기·문 열기를 한 함수에 몰아넣으니 예외 처리가 서로를 망가뜨림

무엇이 나아졌나

열 종류 레이어를 한 번의 레이캐스트로 처리하고, 규칙은 시스템별로 분리

핵심 코드 — 레이어 마스크
constexpr uint32_t targetLayerMask =
    layer::Stain::mask | layer::Furniture::mask
  | layer::Pickable::mask | layer::Tool::mask
  | layer::Door::mask   | layer::Switch::mask;  // 이름으로 다룬다

scene.GetPhysicsScene()->Raycast(origin, dir, hits, 10,
                                 range, targetLayerMask);
std::sort(hits.begin(), hits.end());  // 거리순

PhysX API를 그대로 드러내고 싶지 않아 Ray·RaycastHit을 따로 뒀습니다. 비교 연산자를 오버로딩해 두니 정렬만 하면 가장 가까운 것이 맨 앞에 옵니다.

막혔던 지점

들고 있는 가구가 뒤쪽 홀로그램을 가려서 클릭이 안 되는 문제가 있었습니다. 적중 목록의 첫 번째를 무시해야 하는 조건을 상황별로 정해 해결했는데, 규칙이 시스템 안에 있어서 다른 상호작용은 건드리지 않고 고칠 수 있었습니다.

03

회고

잘된 것

지난 엔진보다 에디터가 훨씬 안정적이어서 작업 중에 툴이 죽는 일이 없었습니다.
물리를 별도 모듈로 떼어 둔 덕에 나중에 손대기 편했습니다.
인스펙터 메타데이터를 넣고 나니 같은 자료형도 상황에 맞게 다르게 보여줄 수 있었습니다.

아쉬운 것

씬 버전이 안 맞을 때 try-catch로 막아만 두고 마이그레이션은 끝내 못 만들었습니다.
프리팹을 고쳐도 이미 배치된 것들은 따로 동기화되지 않아서, 기획이 같은 작업을 두 번 해야 했습니다.

다음에 개선한다면

컴포넌트를 버전별로 관리하는 마이그레이션을 넣어, 불일치 항목은 기본값으로 채우고 씬을 열게 하겠습니다.
프리팹은 UID로 고유하게 관리해, 원본을 고치면 이를 사용하는 모든 씬에 반영되도록 하겠습니다.
