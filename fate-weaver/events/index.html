FATE WEAVER · 이벤트 시스템 — 회고 후속

문자열로 부르던 이벤트를
타입으로 부르기까지

회고에 적은 아쉬운 점 가운데 이벤트 ID 하나만 다룹니다. 2세대 엔진의 이벤트 전달 경로와 그 방식이 남긴 비용, 두 세대 뒤에 이를 대체한 방식을 도식으로 정리했습니다.

01

이벤트가 엔진의 중심 통로였습니다

Fate Weaver(2023, 두 번째 자체 엔진)의 이벤트 시스템은 게임 로직에만 쓰이지 않았습니다. 오브젝트 생성과 삭제, 씬 전환 같은 엔진 내부 동작까지 이벤트로 요청했습니다.

이벤트가 엔진의 중심 통로였던 만큼, 식별 방식의 약점이 그대로 비용이 되었습니다.

Engine/SceneSystem.cpp — 엔진 내부 동작도 문자열로 구독합니다
EventSystem::GetInstance()->Subscribe(
    L"CREATE_OBJ",   MakeListenerInfo(&SceneSystem::DelayedCreate));
EventSystem::GetInstance()->Subscribe(
    L"DELETE_OBJ",   MakeListenerInfo(&SceneSystem::DelayedDelete));
EventSystem::GetInstance()->Subscribe(
    L"CHANGE_SCENE", MakeListenerInfo(&SceneSystem::DelayedChange));
02

발행에서 수신까지 — 두 세대의 경로

위가 2세대, 아래가 4세대입니다. 두 경로 모두 발행 · 지연 · 대상 찾기 · 전달을 거칩니다. 달라진 것은 대상을 찾는 기준과, 수신부가 타입을 복원해야 하는지 여부입니다.

Engine/EventSystem.cpp — DispatchEvent
auto [first, last] =
    m_Listeners.equal_range(evt.EventID);

for (auto& it = first; it != last; ++it)
    it->second.EventFunction(evt.Parameter);

// 빈 범위도 오류가 아니다 — 반복문이 실행되지 않을 뿐
Animacore — 정의 · 구독 · 지연 발행
// CoreSystemEvents.h — 이벤트가 구조체입니다
struct OnInputLock { bool isCameraLock; bool isMovementLock; };

// AnimatorSystem.cpp — 구독은 타입으로 합니다
_dispatcher->sink<OnStartSystem>()
    .connect<&AnimatorSystem::startSystem>(this);

// Scene.cpp — 지연 발행
_dispatcher.enqueue<OnCreateEntity>(entity, *this);
03

같은 실수가 검출되는 시점

이벤트 이름을 잘못 적었을 때, 2세대는 실행 중에 아무 반응 없이 넘어가고, 4세대는 컴파일 단계에서 중단됩니다.
